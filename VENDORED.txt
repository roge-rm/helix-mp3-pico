Helix fixed-point MP3 decoder (RealNetworks, RPSL 1.0, see LICENSE.txt and RPSL.txt).

Taken from https://github.com/pschatzmann/arduino-libhelix, commit
f6e55a307c7577c5e3dfe1bf424a61075235fa08, src/libhelix-mp3 (the Helix
sources only, not the C++ wrapper).

Changes here, all made 2026-11-16 (each changed file says so at the top):
- buffers.c rewritten: the decoder state comes from one block given with
  MP3SetPool() (declared in mp3dec.h), no heap.
- mp3dec.h: declares MP3SetPool() and MP3PoolBytes().
- assembly.h: Cortex-M0+ (or MP3_MULHS_C) builds the 32x32 multiply's high
  word from 16-bit products, in inline asm on the M0+; MP3_COUNT_OPS counts
  the long multiplies.
- coder.h, polyphase.c, subband.c, buffers.c: MP3_POLY_SPLIT (on by default
  on the M0+) runs the polyphase filter as dot products of 16-bit pieces
  with 32-bit sums (xmp3_PolyDot(), asm in RAM on the M0+), from a table in
  the decoder state built by MP3InitDecoder(). Exact to the bit.

These files came to helix-mp3-pico from midiTracker
(github.com/roge-rm/midiTracker, lib/helix_mp3). Changes since, 2026-11-16:
- buffers.c: the RealNetworks licence block put back at the top.
- assembly.h: plain pico-sdk builds (PICO_ON_DEVICE) take the same path as
  Arduino.
- helix_mp3_pico.h added: includes mp3dec.h and gives the sizes for static
  buffers (HELIX_MP3_POOL_BYTES, HELIX_MP3_PCM_SAMPLES).
- MPEG-2.5 on and safer on bad data: mp3common.h takes the 11-bit
  syncword; bitstream.c rejects the reserved version; mp3dec.c rejects
  layers 1 and 2, short buffers, stale free-mode state and slot counts that
  don't fit mainBuf; huffman.c and stproc.c keep table indexes in range on
  a bad frame. test/fuzz.c runs random and bit-flipped data under ASan.
